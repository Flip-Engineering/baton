## P0-P1 findings

- **P1 — `evidence_ranked` selector criteria are charged to the wrong ceiling authority.** §93.5 lines 290–293 state: "`ProgramPolicy.maxJoinMembers` bounds Program-level arrays (collect/select items, predicate arity, selector criteria, and the §93.4 canonical-integer classes); the two authorities are never interchangeable." The only selector criteria array is `evidence_ranked.criteria` (§93.9 lines 881–884), which is also the sole 93a.2 instance of the §93.4 canonical-integer classes ("selector `criteria` by `order`", line 232). The implementation bounds it with `policy.maxEvidenceRefs` instead: `control-nodes.mjs:342-343` (`criteria.length > policy.maxEvidenceRefs`). The two fields bind different lower authorities (§93.20 table: `maxJoinMembers` ← Context `maxResultItems`; `maxEvidenceRefs` ← Goal/Plan `limits.maxItems`), so they may legitimately differ; the checked-in fixtures already differ (`maxJoinMembers: 8`, `maxEvidenceRefs: 16`, `impl/test/fixtures/phase93a-program-fixtures.mjs:85-86`), meaning a 9–16-entry criteria array is admitted today although §93.5 caps it at 8, and conversely a deployment with `maxEvidenceRefs < maxJoinMembers` would reject spec-legal Programs. The violating line lives in `control-nodes.mjs`, outside this partition's two named files, but the violated claim is §93.5's ceiling-authority split, which is this partition's assigned text; no other replica's scope covers it. (Note: the same file bounds join/selector `all_verified.contractDigests` by `maxEvidenceRefs` at lines 280-281 and 335-336; the spec states no numeric bound for `contractDigests` anywhere, so that choice is unspecified rather than non-compliant — flagged for completeness only.)
