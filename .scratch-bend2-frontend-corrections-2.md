# A1. A kernel-only success is not a completed check

Retracted: the claim that book_valid(book) completing is the checked proposition, and the implication that the kernel alone yields a CLI-equivalent verdict.
Corrected: the CLI verdict is composed in main.ts book_read, 578-597: after book_load it refuses a PROOF.bend that does not import ./LAWS.bend (583-586, cli_fail), runs book_valid(book, ...) (588), then Comp.book_owned(book, Comp.SYNTH) (591), then refuses when book.hols + book.open > 0 (592-595). The kernel parser increments the hole counter for ?TODO (kernel 2047-2048), and term_check accepts ?TODO at any goal (kernel 3720-3722). A law with a TODO body therefore checks without being proved, and no kernel-only result may be labelled proved.
Packaging consequence, now explicit: Comp (book_owned and SYNTH among others) is not in the inspected distribution, which holds only bend-v2.0.25-kernel.ts and bend-v2.0.25-main.ts. The packaging closure for CLI-equivalent checking is therefore incomplete, and a checked-law claim cannot be scoped from these two files alone.

# A2. A private empty BEND_LIB does not confine the loader

Retracted: the recommendation to redirect BEND_LIB to a private directory as if that blocked the hub.
Corrected: book_load 1027-1039 fetches precisely because the requested cache file is absent (the guard is file.startsWith(BEND_LIB + "/") && !fs.existsSync(file)), so an empty private cache makes hub_get run rather than fail closed. Confinement must come from admission control over loader effects or from a reviewed closed source resolver that refuses a missing import; copying sources into a private directory establishes nothing about network or write behaviour.

# A3. Text identity is not file identity, and parse offsets are post-transformation

Retracted: binding spans to files by Span.src text or hash equality as the safe rule.
Corrected: two distinct paths can hold identical text, so text equality cannot attribute a span; and book_load blanks the import lines (lines[i] = "", then parse_book(book, dir, lines.join("\n"), ns, al) at 1100-1104), so parse offsets address transformed text, not the captured original bytes. The honest construction is call-site file provenance plus an explicit, recorded offset transformation from original bytes to parsed text, never text matching alone. Additionally the alias table lives in the loader al and in Parse, not in the retained Book (Book is tlds/ctrs/order/hols/open/tmps, kernel 314): loader events, including the alias table and import edges, must be captured before al goes out of scope, and import spans remain degenerate (beg === end, 1065).

# A4. Type rendering needs term_lower, and the final tlds loses distinctions

Retracted: using term_show directly on Def.T / ADT.T.
Corrected: Def.T and ADT.T are HTerm (kernel 311-312) while term_show takes an LTerm (1295, term_show(term: LTerm, top = -1, bnd: Name[] = [])); convert with term_lower(term: HTerm, d = 0) (822) first and record that the result is a rendering in a given binder-name list. The final book.tlds also loses the original law-versus-fill distinction and the per-declaration spans: a filling def is stored in the law slot (2540-2542), so duplicate-name detection and law/proof pairing need ordered parse events with source mapping rather than the final map. Bodies can also be transiently null during book_valid, so a query must not infer "unproved law" from v === null observed mid-run.

Corrected anchors in kernel.ts parse_book: the def branch is around 2610-2613, the type/ADT branch begins at 2618 with the ADT record built there (my 2660 was wrong), the law branch begins at 2654 (my 2694 was wrong), and the terminal parse_fail(p, "'def', 'type' or 'law'") is at 2703. Retracted: describing proposed "references" and "callers" facts as resolved. term_refs (main.ts 545) collects the names a term mentions, and applying a function to an argument is syntactic application; a resolved reference or caller relation needs the provider's own resolution step over the Book and its binder structure, and until that exists such facts must be labelled syntactic and unqualified. The subject names cited in the original report were read from the repository bytes (canonical.bend def json_text, escape_char, one; git/text.bend def str_eq, split_nul, enc_argv; this lane def projection_bitval, type Subject), but the relations among them were not resolved and are withdrawn as relation claims.

# A6. Compiler checking is admitted computation, not an effect-free step

Retracted: treating a compiler check as an effect-free read and mapping it to sourceAnalysis without qualification.
Corrected: checking a target program is admitted remote computation with custody and source dependencies (Comp, base.bend, and the loader closure of the examined program); it must not be declared grant-free or effect-free, and no part of it may run locally. My proposed bend2 module paths, the operation_of mapping and the projection names remain provisional pending the shared revised boundary review; they are a proposal, not a settled interface.
