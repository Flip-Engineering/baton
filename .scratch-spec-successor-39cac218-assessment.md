# Bounded corrections

# S1 (Bend2 section, source precision) - the type-rendering conversion is still missing

The successor contains no occurrence of HTerm, LTerm or term_lower. Def.T and ADT.T are HTerm (kernel 311-312) while term_show takes an LTerm (1295), so the declared-type fact the section requires cannot be produced without term_lower(term: HTerm, d = 0) (822), and its output is a printer rendering under a binder-name list rather than a type object. Proposed addition, after the sentence listing the inspected exports: "Declared and inferred types are terms, not printed strings: Def.T/ADT.T are HTerm and term_show accepts LTerm, so a type fact applies term_lower first and records the binder-name list it printed with, alongside the distinct declared, inferred (Infer.ty) and printed statuses."

# S2 (new surface) - the owner rule for module-resolution is unstated

Context.owner_admission (spec 1837-1841) admits a recorded active owner and, for a stopped owner, only owned query-control recover/release and owned runtime release; every ordinary computation subject refuses. `module-resolution` is a new subject that performs a package install outside the target project. The spec must state the rule explicitly. Proposed wording: "module-resolution follows the owner rule for a package operation: inspect is admitted for the query's recorded owner, including a stopped owner that retains an installation duty; install requires a recorded active owner plus the installProvider grant, and is refused for a stopped owner. Its result names the retained installation outcome and is readable through the ordinary result route."

# S3 (activation) - which authority lets a selected provider's own process start

The successor says a query performs "any required selected-module readiness check after admission" (228-229) and that activation verifies the selected implementation and dependency closure (190-192), but the effect vocabulary contains only target effects plus installProvider. Nothing states whether starting the selected provider's own process needs a grant. Proposed wording: "Starting or probing the selected provider's own implementation process is authorized by the declaration and package authority and requires no target effect grant; any target-side operation that process performs retains its declared effect class, and the process start, its identity and its retained output are recorded as evidence. Discovery and unrelated queries start no such process."

# S4 (Bend2 section) - where the parse events come from

The requirement that checked partial facts need fresh-run event evidence is right, but the source consequence should be stated so the extractor is specified honestly: the frontend does not emit events. book.order is appended by parse_def/parse_book (2594 onward), parse-time binder state (Parse.sc.stk, Parse.sc.frs) and the alias table (Parse.al) exist only during parsing, and book_valid mutates the Book (3860-3880). Proposed addition: "Declaration, fill and binder events are captured by the module around its parse and validation calls: Parse.sc and Parse.al must be observed during parsing because they are not retained afterwards, and a checked fact is bound to a fresh run's event evidence rather than to state left by a previous run."

# S5 (Bend2 section) - name resolution functions to cite

The reference/import sentence should cite the functions that actually resolve, so no implementer builds a parallel resolver: parse_lookup (1725) returns the binder entry [Name, index], parse_var (1735) emits Var(name, index, span) for a bound name or Ref(qualified, span) for a dotted name, parse_qual (1747) applies the file namespace and parse_reso (1751) rewrites an alias head through the loader alias table and returns the qualified name only when book.tlds/book.ctrs contains it. Proposed wording: "A resolved reference is the parse-produced binder identity (Var index) or qualified definition name (Ref) together with its parse-time span and the captured alias table; a Ref that resolves to nothing is reported unresolved, and no second name resolver is introduced."
