# MOT4 track cache

The optional `attachMotion7` cache reuses an encoded MOT4 track for an exact caller-supplied recipe. The cache is disabled unless the runtime policy is explicitly qualified and the caller supplies a frozen recipe containing source hashes. No caller recipe generator or qualification record is included, so the shipped integration has no eligible production calls by default.

The cache server route is the shared single-flight store in `cache_server.mjs`. The client uses the Fine7 numeric codec already used by that store's sibling cache. Cache records bind the caller recipe, clip options, source manifest, runtime, dependency closure, and namespace. Unsupported or over-budget inputs, unavailable storage, checksum or metadata mismatch, and replay mismatch fall back to the existing `bakeTrack7` call.

On a hit, the client validates the MOT4 header and the recorded actor report. It initializes cloth rest state, calibrates lids, then replays every actor frame at the same timestamps as `bakeTrack7` to restore the final rig pose and actor side effects. It skips cloth frame simulation and track encoding. It compares the cloth fallback mode, lid calibration stored in the decoded MOT4 header, actor report, and final bone and group transforms. If replay fails validation, it restores the starting transforms and Hero motion memo caches before invoking the original baker.

The actor closure is deterministic for the pinned `CLIPS7` implementation: clip placement and procedural variation use person/options inputs and seeded hash/noise functions. Frame replay preserves stateful wave-arm integration by running every frame in order. The Hero fields `_h0`, `_flex`, `_gest`, and `_fistInfo` hold derived memo data that actor methods may populate. `girdleRhythm7` also stores derived signs in a module-local `WeakMap` keyed by the Hero; replay calculates the same signs. `Hero.update()` refreshes the same corrective and fabric uniforms during each replayed frame. These implementation details must remain covered by the dependency-closure hash and qualification tests. A custom actor module or a changed actor dependency requires a new qualification.

This candidate has only CPU mock tests. It has not run a person build, bake, browser, renderer, or farm job. It makes no measured speedup claim: replay still evaluates every actor frame, so the work saved is cloth frame simulation and MOT4 encoding. Runtime activation requires separate source-bound recipes, exact decoded track and final person-state comparisons, and a measured cold-bake versus hit replay on normal remote capacity.

Run the mock tests with `node --test videos/web/test/mot4_track_cache.test.mjs` from the repository root. They cover default-off behavior, canonical MOT4 header lid metadata, state replay and restoration, exact frame timestamp operation order, publication protocol, and cloth-rest failure handling.
