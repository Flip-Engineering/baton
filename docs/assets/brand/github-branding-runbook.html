GitHub branding runbook

The Flip PFP on the dogfood committer + the org rename. ~10 minutes, all web UI. The avatar file is already in the repo: docs/assets/brand/flip-avatar.png (460×460, this page's header image).

Part 1 — the baton-dogfood bot account + Flip PFP

Why: the campaign's commits land as baton 0.1.0 <baton-dogfood@localhost>. GitHub links commits to accounts by email; a localhost email links nowhere and shows a generic identicon. A real (bot) account gives the committer a face — Flip with the conductor's baton.

1. Create the account

  1. 1In a fresh browser profile (or signed-out window), go to github.com/signup.
  2. 2Username: baton-dogfood (if taken: baton-dogfood-bot).
  3. 3Email: a real mailbox you control (e.g. baton-dogfood@yourdomain or a plus-address like you+baton-dogfood@gmail.com). GitHub requires verification — the account can't take actions until verified.
  4. 4Complete signup; skip the onboarding surveys (any answer is fine).

2. Set the Flip avatar

  1. 1Log in as the bot → top-right avatar → Settings.
  2. 2Profile → Profile picture → Upload a photo…
  3. 3Choose docs/assets/brand/flip-avatar.png from this repo (crop is already square 1:1 — just confirm). Save.

3. Connect the commit identity

GitHub noreply email format: <username>@users.noreply.github.com. Once the handle exists, tell kimi the username (or hand it this line):

git config user.name "baton 0.1.0"
git config user.email "<USERNAME>@users.noreply.github.com"

kimi will then sweep the campaign's commit identity (every wave/driver commit uses -c user.name/-c user.email) so new commits link to the bot and the Flip PFP shows in the history, the contributors graph, and PRs.

4. (Optional) make the bot a real collaborator

  1. 1Repo → Settings → Collaborators and teams → Add people → the bot's handle (Read is enough for display; Write if it should ever push PRs itself).
  2. 2Accept the invite from the bot account (it lands in the bot's email / notifications).

Part 2 — rename the org (Flip-Devs → Flip-Engineering)

Read-first caveats (GitHub's own semantics):

  • Web requests to the old org URL redirect to the new one — but git operations over HTTPS/SSH remotes are not guaranteed to redirect forever; update local remotes promptly (git remote set-url origin git@github.com:Flip-Engineering/<repo>.git).
  • The old org name becomes available for anyone to claim after the rename. If you care about squatting/phishing, register Flip-Devs as an empty placeholder org immediately after.
  • Org rename does not move/retitle issues, projects, or teams — they carry over. GitHub Pages sites under flip-devs.github.io change hostname; external links to raw/Pages content may break.
  • OAuth Apps / GitHub Apps / Actions secrets keep working; any third-party integration keyed on the org name (rather than the immutable org ID) should be re-checked.

The rename (owner account, ~2 minutes)

  1. 1As an org owner: open the org → Settings → General.
  2. 2Scroll to the Danger Zone → Rename organization.
  3. 3Enter Flip-Engineering, confirm the modal, done. Repeat per repo: nothing — repos follow the org automatically.
  4. 4Update local clones: git remote set-url origin git@github.com:Flip-Engineering/<repo>.git (verify with git remote -v).
  5. 5(Recommended) register the old Flip-Devs name as an empty org so nobody else can.

✦(◕‿◕)✦ That's it. After Part 1 step 3, every future baton 0.1.0 commit renders Flip at the conductor's stand. The org rename is instant and reversible (same flow, other direction).
