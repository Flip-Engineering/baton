means the implementation has no equivalent enforcement. The table contains one row for every

## Type-enforced boundaries

The following laws are represented by the input types in `laws.bend`:

- `LAW-AUTH-2`: `UpdateRequest` has the event fields. `AuthenticatedUpdate` adds the boundary-minted
  `Principal`.
- `LAW-CAPTURE-1`: `capture_owned` receives `CaptureRequest` with an affine `OwnedPath`.
- `LAW-CAPACITY-3`: materialization consumes the exact affine `CapacityReservation`.
- `LAW-LEDGER-1`: projection receives `DurableEvent`.
- `LAW-LEDGER-2`: mutation receives `IdempotencyKey` with the pending event.
- `LAW-LEDGER-3`: `EventBatch` has at least one event.
- `LAW-LEDGER-4`: ledger reads consume `ReadBudget`, and recursion decreases that value.
- `LAW-CONTRIBUTION-1`: contract fields and closed values are constructors.
- `LAW-LANDING-1`: landing consumes a value carrying acceptance, merge-base, and green-gate evidence.

These types remove the corresponding invalid shapes from the application API. Bend 2.0.25 imports
every definition in a module and exposes constructors to JavaScript callers. A deployment that treats
`Principal`, `OwnedPath`, or `CapacityReservation` as a security capability must mint an opaque value
in the host effect boundary. The pin provides opaque affine host handles such as `File` and `Socket`.
Custom constructor privacy is absent at this pin.

## Proposed law

`PROPOSED-REVIEW-1`: the contribution author cannot record an `accept` or `reject` review on the same
contribution. Current code enforces independent checking through `self_check_refused`, while
`swarm.contribution_reviewed` derives the reviewer from the caller and permits a caller that also
authored the contribution. No source or test enforces reviewer identity inequality. `laws.bend`
therefore keeps `AuthorPrincipal` and `ReviewerPrincipal` as role capabilities and does not claim an
inequality proof between their underlying principals.
