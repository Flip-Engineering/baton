# PR869 Codex span checkpoint correction

## Context

The combined PR869 and PR901 head `942b6075c` keeps every Codex frame in the
retained stdout spool for an attempt. The PR869 8 MiB tests fail with these
results:

- `test_codex_large_assistant_frame_stays_spanned_through_report` reports
  checkpoint offset 0 instead of 8388608.
- `test_codex_large_failed_terminal_stays_spanned_through_report` reports
  checkpoint offset 0 instead of 8388608.
- `test_codex_large_failed_terminal_replaces_legacy_checkpoint` finds a
  `codex-span-v1` token for a 103-byte legacy assistant line instead of the raw
  line.
- Retained attempts contain `checkpoint-error` `state rejected by the observer;
  replaying from the beginning`. The observer waits in `select`/`poll` and does
  not commit the large frame.

## Root cause

`Turn.retained_output` enables spanned reads for every Codex attempt line.
`Turn.codex_frames_span` then classifies and stores every frame through
`codex_frame_role_sql` and stores a token for assistant and failed-terminal
frames. Two consequences follow.

1. A small legacy line is classified and stored as a span token. The legacy
   text path in `codex_frames_text` is not used, so the raw line is lost.
2. The role SQL and `codex_observation_sql` run `json_extract` or `json_remove`
   over the complete span value. For an 8 MiB frame this parse does not produce
   the assistant or failed-terminal role promptly. The reducer state does not
   change, `Observer.checkpoint_due_fields` returns false, and no checkpoint is
   written. The observer then waits for the next frame. The checkpoint due
   decision has no term for the span cursor itself, so a span whose reducer
   fields are unchanged keeps the cursor at the previous offset.

## Fix

- `Turn.codex_span_prefix_sql` limits frame classification to a 4096-byte
  prefix. If the prefix is not complete JSON, the function appends a closing
  quote and two closing braces. The Codex frame type fields occur before the
  large body strings, so the prefix classifies the generated assistant,
  failed-terminal and completed frames without parsing the retained body.
- `Turn.codex_frame_kind_span_sql`, `Turn.codex_frame_role_sql` and
  `Turn.codex_observation_span_sql` use that prefix. The generic observation of
  a large frame is a small JSON object with the frame type; the exact result
  remains available from the full span at completion.
- Spans of at most 4096 bytes are materialized through
  `Frame.text_result_decoded` and use `codex_frames_text`. The 103-byte legacy
  assistant line is stored raw, and the legacy checkpoint path is preserved.
- `Turn.frame_is_span` adds the span cursor to `checkpoint_enabled`. Every
  consumed span writes the checkpoint cursor, including a span whose reducer
  fields are unchanged or a partial EOF tail. The state is unchanged in that
  case; only the durable cursor advances.

## Expected behavior

- The 8 MiB assistant and failed-terminal frames are classified from the
  prefix, stored as `codex-span-v1` tokens, and committed at the end of the
  span.
- The 103-byte legacy assistant line is stored as raw text.
- A span with no reducer change still advances the checkpoint cursor.
- The exact result, event and report paths continue to read the full message and
  terminal span through `codex_span_result_sql`.

## Limits

This is a source-only change. No candidate build, integrated build, full test
suite or installed-runtime action was run for this patch. The 398d candidate
source snapshot at `.local/state/queue995-997-candidate-398d73b9/source`
contains the pre-PR869 Codex functions; the fix requires the PR869 integration
first and does not apply directly to that snapshot. The exact 8 MiB result
parse, the PR869 result/event/report assertions and the PR901 46,123,112-byte
replay were not re-run. Prefix classification assumes the Codex type fields and
the end of the last body string are covered by the 4096-byte prefix and the
closing suffix.
