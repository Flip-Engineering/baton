## The sharpened decision: run E2, not E1

Every stream, from every angle, converges on the same correction to doc 07/13's "run the M1 eval": **the M1 eval as framed (E1 — "does a supervised cross-vendor fleet beat a single-vendor soloist?") is the wrong first experiment.** It tests the *rental* (the Conductor), costs weeks (supervisor + adapters + event-loop + fault-injection), and is confounded by adapter quality, GLM throttling, brief quality, and the coordination tax. The kill-case stream named the experiment that **dominates** it as a decision instrument:

> **E2 — Does independent cross-vendor verification catch material defects that same-vendor verification misses, at a decorrelation rate that justifies a second vendor's cost?**

E2 tests the **moat** (the Referee), not the rental. It needs **zero baton infrastructure** — two `--json` artifact consumers and a fixed corpus of ~50 real diffs (some with known/injected material defects), graded against a **human-pinned** spec in a sandbox no worker controls. It runs in **days on hardware you already have**. And it is *two-sided*: if cross-vendor lift over a *strong* same-vendor baseline is within noise — the sharpest risk in the whole corpus (doc 13 T1: "N LLMs share training priors, so on an ambiguous spec they converge on the *same* wrong answer and `agree:true` fires") — then **the cross-vendor premise is dead at the root and the entire project, Conductor and Referee alike, should not be built.** If the lift is material *and the misses are decorrelated* (different families miss *different* bugs — the real asset), then the Referee is real and everything else becomes downstream optimization.

Two guardrails E2 must survive or it re-inherits the eval's own red-team (doc 14 #21): the same-vendor baseline must be **strong** (well-briefed, same pinned spec — not a scarecrow), and the corpus must not be cherry-picked toward bugs one family is structurally bad at. Put adversarial review on the E2 *design* before running it.

**This is the whole recommendation in one line:** don't build baton and don't do nothing — build E2, the cheapest experiment that can *kill* the project, aimed at the moat, and refuse to write another line of Conductor spec until its pre-committed decorrelation threshold survives its own review.

## What each stream actually concluded (build-first / key correction)

- **Eval design** → The sealed grader is **I7 lifted one level**: re-execute the arm's diff in a fresh container the arm can't touch, overlay the *canonical* held-out tests on top (a weakened in-repo test is discarded), grade on `FAIL_TO_PASS` + `PASS_TO_PASS` (SWE-bench-Verified substrate). Fix the red team's real hit: **one fixed USD+wall cap applied identically to both arms** (budget parity was self-contradictory). And the value decomposition pre-registers **PIVOT-TO-REFEREE** as a named outcome — if lift concentrates in verification+review, the eval *measures* doc 13's reframe instead of arguing it.
- **Security & alignment** → Concede the sharpest hit flatly: **baton is not CaMeL/dual-LLM** — the worker *is* the injectable planner, so the label algebra is a **hub-level authority boundary on merges/grants**, not token-level injection immunity. The real unpatched hole: **a passing DoD is not a security spec** — insecure-but-tests-pass merges. Fix: the merge gate needs a security-class check (effect-diff: did this add a network/exec/secret-read capability?), not just the DoD. Provenance `inputs` must be **hub-observed, not worker-self-reported** (a worker omits a causal parent to hide contagion).
- **Scheduler & economics** → The moat is **not the routing table** (a 5-tuple `harness×model×mode×class×difficulty` is thousands of cells against N≤10 — unlearnable). The durable thing is **I7 firing on every task**; routing's learnable early signal is only coarse `(harness×class)` ("Codex reliably fails auth-refactors"). Cross-pool cost is **not a scalar** — it's a resource-allocation decision (prefer the least-scarce resource for equal verified value), because a fabricated GLM dollar can't be compared to a real Codex dollar at the seam.
- **HITL & operator** → The fact/prose boundary (doc 12 §1b) must be enforced **in the operator surface, not just the ledger** — trusted hub-computed facts render as facts, untrusted worker prose renders delimited and never as authority. The narrative's **temporal** core (events-since-last-look) survives; the elaborate cross-sectional "storyline-DAG plot model" is a mirage at N≤5 — cut it. And a real bug: **`rationale` must never block the emergency `fleet_kill`/`fleet_interrupt` path** — a required prose field on the fire-extinguisher is a defect.
- **Failure & chaos ops** → Honest downgrade: workers **do not survive hub death for 2/3 of the fleet** (Claude/GLM are in-hub stdio children per the adapter contract), so the recovery guarantee becomes *"no committed-turn work lost; at most one in-flight turn re-run,"* via `session_ref` resume. Darwin-specific: `boot_id` liveness is Linux-shaped — use `pid_alive ∧ process_start_time`. Disk-full needs a **pre-reserved ledger tail** so the terminal halt record can always be written (the bootstrap paradox). Chaos/fault-injection is the discipline that turns the supervisor invariants from prose into tested properties.
- **Beyond-frontier** → The boldest ideas don't add a plane; they **relocate what baton is**. The three that survived as moats: **(#1) baton as a neutral trust institution vendors route *through*** (neutrality is structurally unbuildable by any incumbent — doc 01 §6 taken to its conclusion); **(#2) the orchestrator is not an LLM** (matches doc 16 Pivot 1 — attacks its own rental); **(#12) the reproducible run corpus *is* the moat** — a data flywheel/time-machine no single vendor can assemble because none sees cross-vendor outcomes on your tasks (doc 14 #14/#20 promoted from feature to thesis). Honest mirages flagged: internal compute markets at N≤10, ZK-proving reasoning, staking non-consenting vendors.
- **Kill-case** → (above) E2 dominates E1; build the one artifact that tells you whether to build baton at all.

## The reframe worth sitting with

Three independent streams (kill-case, beyond-frontier #1/#12, and doc 16) arrive at the same relocation: **baton's durable identity may not be "a thing that drives a fleet" but "a neutral, cross-vendor verification-and-memory institution"** — the Referee plus the reproducible run corpus it accumulates. That object is: unbuildable by any incumbent (neutrality), ToS-clean (consumes artifacts), bitter-lesson-proof (it's the verify half + a private dataset), and it makes the Conductor an *optional consumer* of its trust, not the product. E2 is precisely the experiment that tests whether that institution has a reason to exist.

## How this lands against what's already built

- The **prototype** (`prototype/`) already embodies doc 16 Pivot 1 (deterministic orchestrator, LLMs only as workers) and the Referee as the trust gate — and its self-critique (`prototype/CRITIQUE.md`) caught three painted-on claims and fixed them (real concurrency, fresh-sandbox re-verification, model-diverse fleet). It is the *shape* E2's harness extends: E2 is the prototype's Referee + eval, pointed at real diffs with a human-pinned grader, minus the orchestrator entirely.
- **Language** (doc 17): E2 needs no daemon, so build it in whatever is fastest (the TS prototype, or a Python script — Python is ideal for the eval/stats). The Elixir/Go core question doesn't arise until *after* E2 says "build the thing."
- The corpus's own discipline, finally executed: doc 07/11/13/14/16 all say "measure first." E2 is that instruction sharpened to the cheapest experiment that can kill the project, aimed at the moat.

## Bottom line

The exhaustive campaign did not find a reason to expand baton; it found, from seven independent directions, a reason to **contract it to one experiment**. The honest next artifact is not doc 19 and not the supervisor — it is **E2**: a few-hundred-line, human-graded, cross-vendor decorrelation test on real diffs, with a pre-committed kill threshold. Everything above the Referee is a bet that E2's number licenses. If the number is favorable, the beyond-frontier reframe (neutral trust institution + run-corpus flywheel) is the shape to build toward, in Elixir/OTP or Go, with the Conductor as an earned branch. If it isn't, the campaign will have saved months — and that is a *successful* outcome, exactly the null the eval was designed to be able to confirm.
