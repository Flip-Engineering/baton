## Finding: abort can be recorded as a successful settlement

After each `complete({ signal })`, the script enforces the terminal `completed` state only when `controller.signal.aborted` is false. Consequently, if `complete()` resolves after SIGINT/SIGTERM with the call still cancelled, stopping, or otherwise unsettled, the map path continues into `context.reduce(mapped)` and the reduce path continues into a success-shaped `record` with no `failure`; zero output items also are not rejected. The emitted evidence and process exit can therefore treat interrupted partial results as a successful run, losing exact result and lineage truth. An aborted call—or any post-`complete()` state other than `completed`—must set the run failure and prevent reduction/success recording while cleanup still reaps the descendants.
