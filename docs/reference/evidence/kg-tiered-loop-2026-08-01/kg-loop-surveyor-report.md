## Lease issuance

A lease's shape is fixed by this module before any runtime site can issue one. The capability surface a working parent must carry is the frozen enum `RUN_ORCHESTRATOR_CAPABILITIES` — `run.context`, `run.start`, `run.status`, `run.stop` (`impl/src/run-lineage.mjs:14-16`) — so an issued lease binds exactly those four operations and nothing invented. The per-run geometry that bounds issuance is `DEFAULT_RUN_LINEAGE_POLICY`: `maxDepth: 4`, `maxChildrenPerRun: 8`, `maxDescendantsPerRoot: 32`, and a `leaseTtlMs` of 30 minutes (`:22-28`). Every policy — default or caller-supplied — is forced through `normalizeRunLineagePolicy` (`:39-62`), which rejects anything that is not the canonical 5-field key set (or the opted-in 6-field REPL set) with `schemaVersion === 1` (`:44-47`), so issuance can never run against an unvalidated or shape-drifted policy. The `leaseTtlMs` field (`:27`) is the lease's time bound. The surveyor note's "parent run must not be stopping when the lease is issued" precondition is enforced at the admission site this policy feeds — this module provides the bounds and the capability enum, not the admission-time check itself.

## Revocation

The revocation taxonomy is a frozen, closed enum, `RUN_ORCHESTRATOR_REVOCATION_REASONS`: `operator`, `parent_terminal`, `parent_run_stopping`, `session_revoked`, `superseded` (`impl/src/run-lineage.mjs:18-20`). A lease is therefore torn down for exactly one of these five reasons — never an ad-hoc string — and `parent_run_stopping` (`:19`) is the explicit hook by which a parent run transitioning to stopping revokes its children's leases. Because the enum is `Object.freeze`d and exported (`:18`), the runtime revocation path cannot widen or rename a reason without amending this single source; the surveyor records the five reasons verbatim as the contract the orchestrator-elevation tier must honor.

## What the orchestrator must guarantee

The invariants this module enforces are the guarantees the orchestrator must not violate: a valid lineage policy is a frozen object (`:39-62`) whose `maxDepth`, `maxChildrenPerRun`, `maxDescendantsPerRoot`, and `leaseTtlMs` are positive safe integers (`:49-50`) and stay under the deployment ceilings (`maxDepth ≤ 1024`, children ≤ 100 000, descendants ≤ 1 000 000, TTL ≤ 24 h at `:57-59`). Two guarantees follow directly for the loop. **(1) Digest stability:** `normalizeRunLineagePolicy` accepts only the exact 5-field or 6-field key set (`:44-47`), so the policy digest stays byte-identical across pre-REPL and REPL-opt-in deployments — the orchestrator must not inject extra fields, or the policy is rejected (`fail()` at `:33-37`, `:47`). **(2) Settle-before-stop ordering:** because `parent_run_stopping` is a first-class revocation reason (`:19`), a parent run that begins stopping revokes its children's leases; the hand-off doubt — whether a stopped parent additionally refuses a *fresh* lease at admission via `_assertRunAdmissionOpen` → `run_stopping` — is the open question reserved for the orchestrator-elevation tier. This module guarantees the taxonomy and the numeric bounds; the admission-time refusal is decided downstream of the schema surveyed here.
