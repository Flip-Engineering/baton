## Lease issuance

`run-lineage.mjs` does not hold the issuance call site; it supplies what an issuer *binds* and the *bounds* it obeys. The capability set an orchestrator lease carries is the frozen `RUN_ORCHESTRATOR_CAPABILITIES` (`impl/src/run-lineage.mjs:14-16`): `run.context`, `run.start`, `run.status`, `run.stop`. The lineage a lease may spawn is bounded by `DEFAULT_RUN_LINEAGE_POLICY` (`:22-28`) — `maxDepth` 4, `maxChildrenPerRun` 8, `maxDescendantsPerRoot` 32, and a `leaseTtlMs` of 30 minutes (`:27`). Any policy handed to issuance is forced through `normalizeRunLineagePolicy` (`:39-62`), which rejects unrecognized key sets or non-`schemaVersion:1` policies (`:44-46`), requires positive integers for the four numeric fields (`:49-51`), and caps them at deployment ceilings (`:57-60`), returning a frozen, normalized policy (`:61`). Issuance can therefore proceed only against a well-formed, immutable policy. (The actual issuance entry points — `issueRunOrchestratorLease` / `admitRunLineage` — are surfaced in `impl/src/coordinator.mjs:256,789` and assert admission open against the parent run in `impl/src/coordination-store.mjs:1588,1684`.)

## Revocation

This file defines the revocation *taxonomy*, not the revocation routine. `RUN_ORCHESTRATOR_REVOCATION_REASONS` (`impl/src/run-lineage.mjs:18-20`) enumerates exactly five closed reasons — `operator`, `parent_terminal`, `parent_run_stopping`, `session_revoked`, `superseded`. The `parent_run_stopping` member (`:19`) is the in-file evidence that a lease bound to a stopping parent run is revoked (or sustained as inactive): the revoke site (`impl/src/coordination-store.mjs:1799` `revokeRunOrchestratorLease`) and the lease-state reducer (`impl/src/coordination-store.mjs:11229`, which returns `{ state: 'inactive', reason: 'parent_run_stopping' }` when the parent run is stopping) consume this frozen set rather than inventing a reason. The `leaseTtlMs` ceiling — default 30 min (`:27`), hard-bounded to 24 h at `:57-58` — is the time backstop: even an un-revoked lease cannot outlive its TTL.

## What the orchestrator must guarantee

Three invariants are enforced at policy-load time by `normalizeRunLineagePolicy` (`impl/src/run-lineage.mjs:39-62`). (1) **Schema correctness** — `schemaVersion === 1` and a recognized 5- or 6-field key set (`:44-46`); the optional 6th field `maxReplManifestsPerRun` is itself range-checked (`:52-56`). (2) **Positive-integer shape** for `maxDepth` / `maxChildrenPerRun` / `maxDescendantsPerRoot` / `leaseTtlMs` (`:49-51`). (3) **Deployment ceilings** — `maxDepth ≤ 1024`, `maxChildrenPerRun ≤ 100000`, `maxDescendantsPerRoot ≤ 1000000`, `leaseTtlMs ≤ 24 h` (`:57-60`); each value is *derived* (see the REPL-1 derivation comment at `:5-12`), not an invented magic constant. Beyond validation, the orchestrator depends on **immutability**: every exported set and the returned policy are `Object.freeze`d (`:1`, `:12`, `:14`, `:18`, `:22`, `:61`), so the capability set, revocation reasons, and policy cannot be mutated after load. Cross-module honesty on the survey **doubt**: the admission-time refusal it asks about is confirmed — `_assertRunAdmissionOpen` (`impl/src/coordination-store.mjs:7234-7237`) throws `run_stopping` for a stopping run and is called at lease admission on `lease.parent.runId` (`impl/src/coordination-store.mjs:1684`); a stopped parent run therefore refuses a new orchestrator lease at admission time, so the settle-time ritual must run before run stop. That enforcement is **not** in this 62-line module — `run-lineage.mjs` supplies the taxonomy and bounds; `coordination-store.mjs` enforces them.
