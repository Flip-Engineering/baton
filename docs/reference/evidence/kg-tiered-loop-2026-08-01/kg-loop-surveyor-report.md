## Lease issuance

A run-orchestrator lease is defined first by what it grants: the frozen capability set `RUN_ORCHESTRATOR_CAPABILITIES` — `run.context`, `run.start`, `run.status`, `run.stop` (`impl/src/run-lineage.mjs:14-16`). The lease is bounded, not perpetual — it draws its TTL and structural caps from the lineage policy, which defaults to `leaseTtlMs: 30 * 60 * 1_000` (30 min) with `maxDepth: 4`, `maxChildrenPerRun: 8`, `maxDescendantsPerRoot: 32` (`impl/src/run-lineage.mjs:22-28`). No lease is issued against an unvalidated policy: `normalizeRunLineagePolicy` must run first and enforce `schemaVersion === 1` (`:46`), positive safe-integer shape fields (`:49-51`), an optional REPL ceiling that is a positive safe integer ≤ 100,000 and only present on the extended 6-field policy (`:52-56`), and the deployment ceilings (`:57-60`). The lease binds a working parent task carrying the `baton_orchestrator` capability; critically, a parent run must not be stopping at issuance — that invariant surfaces in this module as the `parent_run_stopping` revocation reason (`:18-20`), and the admission-open refusal (`_assertRunAdmissionOpen`, which throws `run_stopping` for stopped runs) is the orchestrator-side counterpart that consumes this vocabulary.

## Revocation

Revocation is closed-world at this layer: a lease can be torn down for exactly one of the frozen `RUN_ORCHESTRATOR_REVOCATION_REASONS` — `operator`, `parent_terminal`, `parent_run_stopping`, `session_revoked`, `superseded` (`impl/src/run-lineage.mjs:18-20`). No other cause is representable here, so any orchestrator that revokes must cite one of these five. Two reasons bind revocation directly to run lineage: `parent_terminal` (the carrying parent task has finished, leaving the lease with nothing to bind) and `parent_run_stopping` (the parent run is winding down, so a held or newly requested lease must be released — the same invariant the admission-open check enforces at issuance, making issuance and revocation symmetric around the stopping boundary). `superseded` covers in-lineage lease replacement, while `session_revoked` and `operator` cover the external withdrawal paths.

## What the orchestrator must guarantee

The orchestrator consuming this module must guarantee three things. First, **every lease is issued under a normalized policy**: `normalizeRunLineagePolicy` must return before any capability is granted, so `schemaVersion === 1` and all caps are positive safe integers within the deployment ceilings (`impl/src/run-lineage.mjs:39-62`); an invalid policy throws `run_lineage_policy_invalid` (`:47`, `:50`) and an over-ceiling policy throws the deployment-ceiling error (`:59`), and neither may silently fall back to defaults. Second, **the policy-digest contract is preserved**: the base 5-field policy (`POLICY_FIELDS`, `:1-3`) is byte-identical to pre-REPL deployments, and the per-run REPL ceiling is opt-in only via the 6-field `REPL_POLICY_FIELDS` (`:12`, `:42-45`) — an orchestrator must not inject `maxReplManifestsPerRun` (`:31`) unless it intends to alter that digest. Third, **the issuance/revocation ordering holds**: because `parent_run_stopping` is terminal for a lease (`:18-20`), the settle-time ritual (the admission-open check) must run *before* run stop, so a parent never enters `stopping` while still holding — or being granted — an orchestrator lease.
