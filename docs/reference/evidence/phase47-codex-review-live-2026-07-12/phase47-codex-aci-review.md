## Verdict

**Reject Phase 47 at `51217cf` (P1).** Deployment repository binding and direct-versus-web/MCP path treatment are substantially implemented: `createDriver` compares `deploymentRepoId()` with the deployment `repoId` (`impl/src/index.mjs:245-259`), Cairn checks every causal context against the closed policy (`impl/src/cairn-run-scorecard.mjs:110-114`), and audit reverify requires the local path for direct claims while permitting its transport redaction for web/MCP (`impl/src/cairn-run-scorecard.mjs:282-288`). However, northbound idempotency is only syntax-checked, existing artifact verification performs an unbounded read, and cancellation can be crossed before artifact publication. These are confirmed Phase 47 contract defects, not Phase 48 recall work.

The spec's lexical/graph recall, promotion breadth, recall feedback, and deployment-neutral export remain explicitly retained future work under CA10; they are not findings here.

## P0-P1 findings

1. **P1 — causal ACI idempotency identity is not bound to the request or result.** CA1 requires the authenticated northbound idempotency identity, and the review brief specifically calls for idempotency binding. `CapabilityRegistry._ctx` validates the key, then `_run` creates a fresh random `invocationId`; its durable start/completion records omit the idempotency key and request digest (`impl/src/capability-registry.mjs:129-145`). Cairn likewise checks only that a key is nonempty and bounded (`impl/src/cairn-run-scorecard.mjs:110-114`); neither `invoke` nor `reverify` records or compares a binding. Consequently the same authenticated key can invoke different operations, boundaries, or node IDs and all execute successfully instead of returning the original result or an idempotency conflict. The purported transport test uses a different key for each call and only proves presence/forwarding (`impl/test/phase47-cairn-causal-audit.test.mjs:202-224`), so it does not test binding.

2. **P1 — an occupied content-addressed artifact path is read before its size is bounded.** `_causalAudit` limits newly generated bytes, but when the digest path already exists it executes `readFileSync(path)` before comparing content, without first requiring `stat.size === refs[0].bytes` or `<= maxArtifactBytes` (`impl/src/cairn-run-scorecard.mjs:139-143`). Reverify reads it again without a size gate (`impl/src/cairn-run-scorecard.mjs:282-285`). A local filesystem occupant can therefore make invoke/reverify allocate and hash an arbitrarily large file despite CA1/CA7's independent artifact-byte ceiling. The current test checks digest, mode, deletion, and generation max+1, but never an oversized pre-existing digest-path occupant (`impl/test/phase47-cairn-causal-audit.test.mjs:143-160`). This is a resource-bounding defect even though the invalid content is eventually refused.

3. **P1 — cancellation is not rechecked at the artifact publication boundary.** Audit checks the signal after `auditKnowledge`, then calls deployment-supplied `observationTime`, constructs and bounds the result, and may write the packet without another check (`impl/src/cairn-run-scorecard.mjs:133-145`). If cancellation becomes observable in that interval, the operation publishes an artifact and returns success, violating cancellation's no-publication expectation. This seam is real because the constructor accepts the coordination implementation by interface, not concrete identity. The existing red test aborts only inside `auditKnowledge`, exactly before the second check (`impl/test/phase47-cairn-causal-audit.test.mjs:162`), leaving the later boundary uncovered. Trace has no artifact side effect and rechecks after traversal (`impl/src/cairn-run-scorecard.mjs:148-153`), so this finding is audit-specific.

## Required red tests

1. Through the real `CapabilityRegistry`, invoke `causal.audit` with key K and boundary A, then reuse K for boundary B and for `causal.trace`. Require deterministic replay of the first request where identical, and a typed conflict for either changed request. Repeat through web and MCP so transport adapters cannot weaken the binding; also assert the durable capability record binds repo, actor, key, action, op, args digest, and terminal result.

2. Compute a valid audit's expected digest path, remove its packet, place a file larger than `maxArtifactBytes` at that exact path, and require invoke and reverify to refuse from metadata before reading/hash allocation. Instrument the filesystem reader (or expose a bounded reader seam) to prove no oversized `readFileSync` occurs.

3. Wrap `observationTime` so it aborts the invocation signal after metrics are computed. Require `causal.audit` to reject with `cancelled`, leave the artifact directory empty, and emit no completed capability record. Add the same assertion immediately before an existing-artifact acceptance path to cover both write and reuse publication.

4. Retain the existing positive transport split, but make it explicit: direct reverify must reject a missing or substituted path; web/MCP reverify must accept only an omitted path, reject any supplied substituted path, and still compare every public claim field. This is a regression lock for the currently correct seam, not a claimed defect.
