## What landed

- **`run scratchpad append RUN --scope shared|worker:ID [--kind note|plan|doubt|link] --body TEXT|JSON`**
  → `run.scratchpad.append` with the closed `{runId, scope, kind, body}` arg closure. `kind` defaults
  to `note`; `--scope` is validated against the closed `shared|worker:ID` set (mirroring the read
  branch); the non-note body is JSON-parsed and shape-checked against the kernel's closed per-kind
  shape (`normalizeScratchpadEntry`, coordination-store.mjs:607-696) via a new `scratchpadAppendBody`
  helper — a malformed or wrong-shaped body refuses `cli_invalid` naming the expected shape (A1-1, A1-2).
- **bare/unknown `run scratchpad` teaching** — bare `run scratchpad` refuses `run scratchpad requires
  a subcommand: read|elevate|append`; an unknown subverb names the unknown AND restates the closed set
  (A9-1, A9-2). The old `unexpected argument undefined` is gone.
- **`run watch RUN_ID`** → `run.watch` (the canonical operation, `applicationOperationAliasMap` →
  `run.follow`); bare `run watch` refuses `cli_invalid` value-required (`Run ID is invalid`) — never a
  silent `run.start` reinterpretation (R1, R4).
- **`baton application help`** served beside `baton help` / `baton --help` — the registry's canonical
  `deriveSurfaceNames('application.help').cli` spelling — so the R5 taught-Verb column never reads as a
  refusal (R5).
- **#155 typo-guard restructure** (the cli-silent-start capability rows): `RUN_FACADE_VERBS` →
  `FACADE_NOUNS` + `ALIAS_FIRST_TOKENS` (plain arrays, so the maximal-set source-scan still resolves to
  `lifecycleActions`); `RUN_RECOGNIZED_FIRST_TOKENS` is the ONE spread-composed derivation symbol the
  guard consumes; `cliRunVerbTypoRefusal` now emits the refused-position text (follow/steer/member) and
  `did you mean 'run <neighbor>'` + the run-start escape; the bare `run member` prefix teaches the closed
  subverb set. Detection set stays **39** (watch excluded), honoring PT-7/PT-4.
