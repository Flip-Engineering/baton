# Three-part notes: reflexive orchestration, from the trap to the steering acts

## 1. the trap

`lifecycle.turn_completed {status:'completed'}` is an automatic result claim: the coordinator launches the trust gate at every provider turn end, and ordinary agent work — thinking, waiting on tools or test suites — pauses constantly, so the gate kills those pauses with `required_effect_absent` (docs/35 §1). The fix is declared up front and shapes everything downstream: turn-based limits make smart systems shallow and brittle, so steer programmatically and never gate on turn boundaries. The mechanism is an adapter-card declaration `card().turnCompletion ∈ { 'claim', 'pausable' }` defaulting to today's `'claim'` semantics; a `'pausable'`-carded turn end mints a durable `turn.paused` record and moves the task to a new non-terminal `paused` state, and a pause admitted for a run with no live `steering.registered` registration auto-settles immediately with a receipt `turn.settled { actor:'policy', basis:'auto_no_driver' }` so every driverless flow keeps working unchanged.

## 2. decisions

The reflexive-orchestration doc's first gap (G1) is that a worker can ask a free-text question but cannot pose a *decision*: a bounded, typed choice the orchestrator must settle exactly once before work continues. REFLEX-1 closes it with a durable, fenced, single-consumer `DecisionRequest` — `options: exact{id,label,summary}[1..8]` plus an explicit `allowFreeResponse` escape and a mandatory `deadlineMs`, settled through `decision.requested`/`decision.settled` ledger events where first settle wins and everyone else reads a typed `already_resolved` result (docs/32 §3.1). The design explicitly fixes four inherited machinery defects rather than inheriting them: pending interaction records are in-memory only and wedge after a restart, stale-discarded answers get recorded as resolutions, cross-kind settlement lacks kind checks, and duplicate requestIds silently overwrite pending records.

## 3. objects

The REPL layer starts from the permanent constraint that there is no arbitrary-code REPL, ever (§93.1(1)): a "REPL" here is a read-eval-print loop over closed, content-addressed objects computed through the Bench's 14 pure ops + 4 predicates and passed by digest. Docs/33 names three gaps and one closed design: the `ReplManifest` (a second manifest shape with its own digest basis kind string `baton.repl_manifest`, admitted through the single new event kind `repl.manifest_admitted`), named bindings mapping `(scope, name) → cell:<sha256>` via `repl.binding_set`/`repl.binding_dropped` under a per-scope replay-derivable fence, and `cell:` branch refs resolved at manifest admission with the resolved artifact digest recorded in the admission event payload so replay needs no store lookup. Only settled, durably admitted cells resolve — the F12 rule — and every new event kind ships its full fold surface (`_apply` branch, `PROJECTION_CHECKPOINT_FIELDS` entry, `snapshot()` exposure, run-stop guard) in the same commit, with an event-kind inventory test so an incomplete fold fails at test time, not at replay.

## 4. memory

The knowledge-horizons doc opens with the surprising truth that baton already owns the KG: the Cairn system is complete and durable, so the work is three horizon projections over it, promotion paths between them, and closing the activation gap. The three horizons are task (ephemeral: board items, scratch facts, pending interactions, the worker's own REPL bindings — dies with the task), workflow (run-scoped: all boards, packages, cells, reports, and decision settlements for one run), and project (persistent: the existing Cairn KG), each cached keyed to the union of its constituent replay-derivable fences with no new counter invented (docs/34 rule 4). Activation is `recallPreview`: a non-evented, cached briefing projection that appends nothing, injects at the provider-brief seam without touching `briefDigest`, ranks `Contradicts`-joined nodes first with an explicit WARNING marker, and on any refusal ceiling degrades to an honest `briefingUnavailable` marker and lets dispatch proceed — briefings are best-effort, never a dispatch blocker.

## 5. manifests

The REPL-1 decisions contract fixes the ReplManifest authority concretely: a distinct `normalizeReplManifest` with a disjoint digest basis (`kind === 'baton.repl_manifest'`, the `repl` coordinate `{ runId, replRole }` replacing the whole Workflow coordinate block), so a Workflow manifest can never be reinterpreted as a REPL one and no existing digest changes basis. Admission is the authority record — one event kind `repl.manifest_admitted` carrying `{ manifestDigest, runId, replRole, principal, requestDigest }` — and no caller-supplied owner string ever reaches the store: `shared` scope is authenticated through the existing orchestrator lease with the extra pin `lease.parent.runId === payload.runId` (the P1-4 cross-run bleed fix, refused as `repl_manifest_authority_denied`), and `worker:<id>` scope is wrapper-bound, with the store verifying `manifest.repl.replRole === 'worker:' + auth.principalId` since the digest-covered field cannot be rewritten without tripping `repl_manifest_digest_mismatch`. The contract is explicit that this narrowly supersedes reflex4's scope boundaries: the evaluator stays pure and the `context.*` cell computation is untouched; only the authority layer grows one event kind, with every edit enumerated by name.

## 6. steering

The 31-b contract fixes the three steering acts on a live pause registration, each reserving its own single-consumer slot on 31-a's `_pausedTurns` record and carrying its own authority op. `nudge` is a full fresh-turn admission, not a resend: reserve the record, `_admitProviderTurn`, then on adapter ack `bumpTurn`, a same-task `paused→working` unpark, budget re-arm, `_resetWatchdogTurn` (the step that actually re-arms the watchdog, since `turn_completed` only clears it), and scratch-only fence-filtered claim expiry via the `_expireScratchClaims` mirror — never `claimScratch`, the named trap. `wait` is the legal zero-cost park: it never touches the record's state, appending only a durable `turn.wait_noted {pauseId, actor}` receipt so a later `nudge` or `claim` on the same pause still proceeds (the P0-1 wedge fix). `claim` — renamed from `settle`, which collides with `wave.settle` — re-runs the live `_runTrustGate` against a fresh worktree capture (the pause's stored `changedPathsDigest` serves attention classification only and is never gate input) and resolves to the gate's only two terminal verdicts, `completed` or `failed`; `claim` and the worker's own done-signal are the only two paths to required-effect/verification evaluation.

## 7. pause records

The 31-a contract is the backward-compat spine everything above rests on: the card declaration, the pause record, the `paused` state lifecycle, steering registration at run creation, and degenerate auto-settle — with the standing requirement that the suite stays green unchanged. The pause record is deliberately the interaction family's exact single-consumer shape reused verbatim, not a new authority model: a durable per-worker log entry `turn.paused { taskId, turnEpoch, changedPathsDigest }` minted via `appendAttributed`, mirrored by an in-memory record in the `_pausedTurns` map keyed `pause:${task.id}:${seq}` with `{state:'pending', resolution:null, consumer:null}`, plus a durable `_coordTransition(task, 'paused', ...)` riding the existing generic `task.transitioned` event kind (zero new fold code). The whole mechanism hangs on one read site: `_turnCompletionOf(handle)` returns `card().turnCompletion ?? 'claim'`, so MockAdapter and every test card take the byte-identical `'claim'` path with zero churn, while the five production identities declare `'pausable'` — enforced by a card-completeness lint with a closed five-entry registry. A pause minted on a run with no live `steering.registered {runId, driverKind, actor}` marker auto-settles synchronously with `turn.settled {actor:'policy', basis:'auto_no_driver'}`; only a live driver registration lets the task actually stay `paused`.

## 8. red team (31-a)

The 31-a revision brief is adversarial review doing its job before a line shipped: five P1 findings, each caught against the live tree rather than the design doc's stale citations. The blocking one, P1-1, is that `normalizeIntent` (application.mjs:919-921) enforces a closed intent key set and rebuilds the intent with only those keys, so `driverKind` never reached the handler — as written, wave.mjs's member-admission edit would have made every `runs.start` throw and turned the wave-driver suite red. The others are of the same mechanical kind: P1-2 is a fold-order trap (story.mjs folds `turn_completed` to `'idle'` before `turn.paused` arrives, so the transition map needed `{from: ['working', 'idle'], to: 'paused'}` or a parked worker renders idle — dishonest); P1-3 is CI6 replay killing a mid-pause task with `session_not_reattached` after a restart; P1-4 defers the wave.mjs:151 edit to 31-b because a pausable wave member would otherwise park with zero consumption paths and a cleared watchdog; P1-5 is `changedPathsDigest` throwing `captured_change_invalid` when `baseSha` is absent, fixed with the `canonicalDigest([])` skip rule. The brief also pins the cross-contract SHARED DECISIONS — the `_pausedTurns` key space, story.mjs's `'paused'` status winning, `attentionFrom('paused') → 'turn_checkpoint'` living in 31-b, and the coordination-store.mjs:10630/:10637 edits belonging to 31-a — so the two sibling contracts could not drift apart, and it ends by listing what was verified clean so the v2 pass did not re-litigate it.

## 9. red team (31-b)

The 31-b revision brief caught two P0 self-contradictions in the steering acts themselves. P0-1 is the wait/wedge contradiction: v1 had wait "consume" the pause record while also claiming later acts stay legal on it — under rule 1's `already_resolved` discipline those cannot both hold, and either reading wedges the task permanently, so the fix is that wait never touches record state and appends only the `turn.wait_noted` receipt, with the red test proving wait → nudge, wait → claim, and idempotent wait → wait. P0-2 is a mechanical impossibility: claim cannot run the trust gate "against changedPathsDigest" because the gate consumes live `_worktrees.capture()` products (`captured.sha`, the `changedPaths` array, baseSha), so v2 states that claim re-runs the live capture at claim time and the digest serves attention classification only. The P1s are equally concrete: P1-3 names coordination-store.mjs:10630 as the real site where any live non-terminal task status collapses to `'dispatched'` — making v1's `node?.state === 'paused'` projection branches dead code until 31-a's edit lands; P1-4 shows nudge's "exact bundle" omitted `_admitProviderTurn` and event-queue draining, which would double-admit a native adapter's synchronous `turn_started` and never re-arm the watchdog; P1-5 corrects over-invalidation to scratch-only, fence-filtered expiry that runs only after successful turn admission, inside the same reservation rollback boundary. The brief's P2 list is citation hygiene of the same standard — the watchdog handler clears rather than re-arms on `turn_completed`, the story map is `LEGAL_TRANSITIONS`, `turn_checkpoint` attention entries need a `requestId`-shaped pauseId for the :8708 `validText` gate — and it ends by listing the grounding citations verified accurate so v2 kept them.
