# WN6 authenticated SSE adversarial review — 2026-07-11

Scope was limited to the Phase 12 authenticated-web specification, `web-stream.mjs`, `web-northbound.mjs`, `web-auth.mjs`, `coordination-store.mjs`, and their Phase 11/12 tests. This is an independent review turn within the same Codex model family, not an independent-vendor review.

## Actionable finding

### Medium — authorization can expire during a synchronous replay batch

**Locations:** `impl/src/web-stream.mjs:201-213`, especially the single liveness check at lines 204-208 followed by the unbounded-by-count loop over `coordination.events(next)` at line 209; authorization predicates are at lines 50-64. The store materializes the entire retained suffix at `impl/src/coordination-store.mjs:217-220`. Existing expiry and revocation regressions cover a later polling tick (`impl/test/phase12-web-stream.test.mjs:182-197` and `impl/test/phase12-web-auth.test.mjs:106-135`), but not expiry within one replay batch.

**Failure sequence:** (1) an authenticated client opens with a valid old cursor and a large retained suffix; (2) `pump()` checks `_liveAuthorized()` once while the credential is still valid; (3) `coordination.events(next)` clones the whole suffix and the loop serializes/writes every event without another time or registry check; (4) the credential expires while that CPU/write batch is executing; (5) later events in the same batch are still read and emitted. Explicit revocation normally cannot interleave with this synchronous JavaScript turn, but an authenticator backed by shared/external liveness state has the same check-to-use granularity, and expiry alone is sufficient. This contradicts WN2's requirement that expiry terminate an open stream before any later event is read. Buffer byte ceilings cap socket backlog, not batch event count or CPU time, so they do not close the seam.

**Impact:** post-expiry disclosure of repository coordination records and a replay-amplified event-loop/CPU denial-of-service window. This is not privilege escalation to fleet control and does not mutate coordinator authority. Severity is Medium because exploitation requires a large readable replay suffix and timing near expiry, while disclosed data remains within the session's formerly authorized repository.

**Required regression:** use a principal whose `isPrincipalActive`/clock becomes inactive after the first replayed event (or a response whose first write advances the clock), queue at least two events, reconnect before both, and assert the second event is absent, the response ends, capacity returns to zero, and `stream_authorization_lost` is audited. The implementation should recheck live authorization before each event is obtained/emitted (or process a tightly bounded chunk and guarantee the same expiry rule).

## Reviewed seams with no additional actionable WN6 finding

- **HTTP authentication, CORS, CSRF:** ticket POST requires HTTPS authentication, JSON, exact allowed origin through stream authorization, and cookie CSRF (`web-northbound.mjs:237-255`); SSE GET reauthenticates and ticket consumption binds origin/session/credential/repository (`web-northbound.mjs:256-265`, `web-stream.mjs:96-109`). CORS reflects only configured origins and permits credentials, never wildcard (`web-northbound.mjs:227-233,297-302`; `web-stream.mjs:219-224`). Bearer requests do not need CSRF, as intended. No CSRF or cross-origin confused-deputy path was found.
- **Ticket replay, IDOR, and leakage:** tickets are 256-bit random secrets, hashed in memory, short-lived, single-use, and bound to session, credential, origin, and the sole repository authority (`web-stream.mjs:66-109`). Consumption rechecks current authorization. A failed open consumes the nonce, which is fail-closed. The URL contains only the expressly non-credential connection nonce; responses and audits use `no-store` and audit only ticket ID. No session credential enters URLs, frames, or coordination audit in the reviewed path.
- **Repository scope:** constructors reject more than one repository for one authority (`web-stream.mjs:25-27`; `web-northbound.mjs:90-100`), and both principal and server allowlists are checked. No relabeling/IDOR seam was found.
- **Snapshot, reconnect, and retention:** the snapshot boundary is captured from `lastSeq`; fresh streams start at `boundary + 1`, reconnect starts at `cursor + 1`, and cursors outside `[max(0,boundary-replayLimit), boundary]` receive audited `snapshot_required` before headers (`web-stream.mjs:126-145,186-199`). Store sequence order is stable and suffix reads are cloned (`coordination-store.mjs:217-222`). At-least-once semantics and snapshot/event IDs are coherent; no fabricated gap was found.
- **Trust/provenance:** frames independently label occurrence/order as authoritative and payload grounding as mixed/claimed/observed/derived where applicable (`web-stream.mjs:147-152,250-257`). The tests specifically prevent a scratch claim inheriting authoritative content trust. Audit transport is observed, not authorization input.
- **Audit ordering and coordination failures:** issuance audit precedes ticket insertion; connection audit precedes headers/snapshot; snapshot, audit, setup, later read, and write failures fail closed or disconnect and release capacity (`web-stream.mjs:85-88,126-131,186-247`). Audit append is durable before in-memory apply in the coordination store (`coordination-store.mjs:62-69,259-260`). Disconnect-audit failure is deliberately non-fatal and creates no fleet side effect.
- **Backpressure/setup/cleanup:** snapshot, data, control, ticket, and connection ceilings are validated; oversized initial state is refused before headers; write refusal/exception ends the stream; close/error handlers and interval cleanup decrement capacity once (`web-stream.mjs:29-40,154-183,186-247`). Browser disconnect never invokes coordinator control. Tests exercise setup/read/write failures, expiry/revocation, and capacity cleanup. Apart from the per-batch authorization finding, no stranded timer/connection or unbounded pending-byte seam was found.

False positives rejected: audit events appearing after a snapshot boundary are ordinary newly appended ordered events, not a snapshot race; a ticket in the SSE query is intentionally a single-purpose nonce rather than an authentication credential; consuming a ticket before a bounded refusal is desirable anti-replay behavior; and `occurrenceTrust: authoritative` does not assert that untrusted payload prose is grounded.

## Residual Phase 12 scope, not WN6 defects

The specification still assigns identity-provider login/bootstrap, refresh and key rotation, a logout HTTP route, complete per-principal/per-IP request and connection quotas, login throttling, trusted-proxy handling, optional resumable WebSocket parity, command-status reconciliation for admitted-but-incomplete commands, readiness/graceful-shutdown behavior, and real browser automation/adversarial acceptance to WN2/WN5/WN8/WN9. Those incomplete verticals are not defects in the reviewed WN6 SSE implementation. Homelab/deployment integration is intentionally excluded.
