# Authenticated WN6 SSE adversarial review — 2026-07-11

## Verdict

No actionable WN6 finding remains in the reviewed scope after the WN6-1 live-expiry/revocation correction. I did not reproduce a CSRF, IDOR, ticket replay, confused-deputy, credential/token leakage, privilege-escalation, fleet-control-on-disconnect, or unbounded-memory seam. This is an independent review turn on the same Codex model family, not an independence claim across model vendors.

Reviewed current files only: `spec/phase12/authenticated-web-northbound.md`; `impl/src/web-stream.mjs`, `web-northbound.mjs`, `web-auth.mjs`, and `coordination-store.mjs`; and the named Phase 11/12 tests. Prior evidence logs were not consulted.

## Seam-by-seam result

- **HTTP authentication, CORS, CSRF, and ticket issue/consume — no finding.** HTTPS is required before ticket issuance (`web-northbound.mjs:237-255`, especially 246-253); cookie issuance additionally requires the session-bound CSRF secret while Bearer authentication remains header-bound. CORS reflects only an exact configured origin (`web-northbound.mjs:227-233,297-301`). Ticket state stores only a SHA-256 secret digest and binds session, credential, origin, and repository (`web-stream.mjs:79-89`); consume checks all bindings plus live authorization and deletes only a valid ticket (`web-stream.mjs:97-110`). A wrong-session/origin guess neither consumes the valid nonce nor reveals which binding failed. The GET query contains the explicitly non-credential, short-lived nonce, never the session credential (`web-northbound.mjs:256-264`). Tests: `phase12-web-stream.test.mjs:25-39`, `phase12-web-northbound.test.mjs:181-251`, `phase12-web-auth.test.mjs:32-46,61-74`.
- **Repository scope / IDOR / deputy boundary — no finding.** Both northbound and stream reject more than one repository per coordination authority (`web-northbound.mjs:90-101`; `web-stream.mjs:24-27`). Issue requires the configured authority repo and the principal allowlist; consume carries only that server-side repo grant (`web-stream.mjs:51-64,82-85,104-110`). Frames derive `resource.repoId` from the grant, not client payload (`web-stream.mjs:148-153`). Thus an identifier cannot relabel an unpartitioned store under another repository. Tests: `phase12-web-stream.test.mjs:122-142`; `phase12-web-northbound.test.mjs:209-251`.
- **Snapshot, reconnect cursor, replay retention — no finding.** Snapshot `lastSeq` is the boundary; a fresh stream emits that snapshot and begins events at boundary + 1, while reconnect begins at supplied cursor + 1 (`web-stream.mjs:127-145,187-190`). Non-integer, future, and count-retention-expired cursors return audited `snapshot_required` before headers (`web-stream.mjs:135-142`). Reads are count-bounded per pump (`web-stream.mjs:210`) and coordination reads honor the limit (`coordination-store.mjs`, `events(fromSeq, limit)`). At-least-once semantics correctly permit duplicates and never fabricate a gap. Tests: `phase12-web-stream.test.mjs:41-72,245-end`.
- **Authorization lifetime — no finding.** Static authorization checks credential expiry (`web-stream.mjs:51-58`); live authorization additionally calls the registry hook fail-closed (`web-stream.mjs:60-65`). Ticket consumption checks it, every pump checks it before reading, and every event checks it again immediately before emission (`web-stream.mjs:104-107,202-217`). `WebSessionStore.isPrincipalActive` re-resolves durable session state and checks revocation, expiry, stable identity, repository, and non-escalated capability/scope (`web-auth.mjs:144-160`). This closes the former large synchronous replay suffix and established-stream revocation seams. Tests: `phase12-web-stream.test.mjs:183-198,245-end`; `phase12-web-auth.test.mjs:106-end`.
- **Backpressure, bounded setup, and DoS — no actionable WN6 defect.** Constructor limits reject invalid sizes/counts (`web-stream.mjs:28-39`). Ticket and active-connection ceilings are explicit (`web-stream.mjs:68-78,121-125`). Snapshot and data frames are byte-bounded; lag control frames have an independent ceiling (`web-stream.mjs:162-183,187-197`). A false `write()` result or projected buffered overflow immediately disconnects rather than accumulating application buffers. Poll reads are bounded. Tests cover invalid ceilings, ticket pruning/ceilings, oversized snapshots, projected buffering, false writes, and thrown socket/read operations (`phase12-web-stream.test.mjs:59-72,106-181,200-243`). Per-IP/principal request rates are absent, but that is WN5/WN9 residual scope, not a defect in WN6's explicit in-memory bounds.
- **Audit ordering and coordination-store failures — no finding.** Issuance audit commits before ticket insertion (`web-stream.mjs:82-89`); connection audit commits before connection count, headers, or snapshot bytes (`web-stream.mjs:187-201,223-234`). Snapshot/cursor/limit refusals audit before returning. Append failure leaves coordination projections unchanged because `_append` writes before applying (`coordination-store.mjs`, `_append`), and tests inject issuance, connection, snapshot, read, and setup failures (`phase12-web-stream.test.mjs:84-104,144-158,200-243`; `phase11-coordination-store.test.mjs:40-44`). Disconnect-audit failure is intentionally best-effort after authority is already closed and cannot cause fleet control (`web-stream.mjs:155-160`).
- **Timer, socket, and connection cleanup — no finding.** `disconnect` is idempotent, decrements exactly once, clears the interval, and is attached to close/error (`web-stream.mjs:155-160,223-226`). Authorization loss, read/write failure, backpressure, and setup exceptions all route through it; the timer is installed only if still open and is unref'd (`web-stream.mjs:202-255`). Browser disconnect never invokes coordinator control. Tests: `phase12-web-stream.test.mjs:74-82,144-181,183-243`.
- **Trust and provenance — no finding.** Every transported coordination event has authoritative occurrence/order, but payload grounding is independently classified (`web-stream.mjs:148-153,258-265`). Snapshots declare mixed content; Scratch claims are claimed, Scratch facts retain their grounding, knowledge retains grounding or defaults derived, and audit claims are merely observed. Transport therefore does not promote payload prose to authoritative truth. Tests: `phase12-web-stream.test.mjs:122-142,160-181`.
- **No hidden fleet side effect — no finding.** The stream owns only snapshot/event/audit calls; no coordinator is passed to `WebEventStream` (`web-stream.mjs:17-24`). Lag, tab loss, expiry, revocation, and socket errors only close SSE. Explicit authenticated command paths separately perform interrupt/kill (`web-northbound.mjs:196-221`).

## Missing regression strength (not current exploitable findings)

- Add an HTTP-level cookie ticket test proving missing/wrong CSRF is refused before `stream.issue`; current CSRF coverage is split between command/session tests and direct stream tests.
- Add an explicit future-cursor and nonnumeric `Last-Event-ID` assertion, plus an assertion that `Last-Event-ID` takes precedence over the optional query cursor.
- Add a live-registry test where revocation occurs during a multi-event synchronous replay and assert that exactly the pre-revocation prefix is emitted; the current injected-liveness replay test covers per-event checks, while the durable registry test covers polling-time revocation separately.
- Add close/error idempotence and post-close timer assertions (emit both events) to make the exactly-once capacity release invariant explicit.
- Add an assertion that a refused/failed open burns its already-consumed single-use ticket. That behavior is fail-closed and not a replay vulnerability, but should remain deliberate.

## Residual Phase 12 scope, not WN6 defects

- **WN2:** identity-provider login/bootstrap, refresh, rotation, logout HTTP route, and custom-provider live-revocation contracts.
- **WN5:** per-principal/per-IP request rates, login throttling, full command-cost quotas/connection quotas across processes, and trusted-proxy address handling.
- **WN8:** deployment secret lifecycle/readiness, trusted reverse-proxy configuration, and graceful process shutdown/drain behavior. Homelab/deployment integration is intentionally excluded.
- **WN9:** real browser automation across login, reconnect, approval, emergency kill, logout/revocation, and no-zombie cleanup; broader adversarial acceptance coverage, including optional WebSocket parity when implemented.

These residuals may block Phase 12 completion, but none is evidence of a defect in the current authenticated WN6 SSE vertical.
