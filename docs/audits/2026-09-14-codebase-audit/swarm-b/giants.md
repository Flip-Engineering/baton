## FRICTIONS

- F1 — impl/src/worktree-capacity.mjs:36 "const LOCK_POLL_MS = 5;" with :232-234 "Atomics.wait(LOCK_WAIT_BUFFER, 0, 0, ms)". Capacity mutations intentionally block the coordinator's event loop in 5ms slices for up to lockWaitMs (default 5s, :37). Every concurrent MCP/CLI/web request stalls behind any capacity lock contention — a documented but fleet-wide latency cliff.
- F2 — impl/src/worktree-capacity.mjs:346-353 "It is therefore never touched: reclamation of a dead lock is refused at the deadline while such a gate exists (an operator removes the file, named by the refusal)". A reaper killed between gate publish and its finally leaves a file that wedges dead-lock reclamation until a human runs rm. An orchestrator cannot self-serve recovery; the fleet cannot reserve capacity until then.
- F3 — impl/src/contribution-service.mjs:64-70 "if (this.pending.has(key)) return this.pending.get(key);". A second caller joining an in-flight check has its abort signal silently ignored — only the first caller's signal can cancel; the second waits for a result it tried to abort.
- F4 — impl/src/log.mjs:226-230 "try { ... } catch { this._floor = 0; }". A corrupt/torn cursor state file silently rewinds the ack floor to 0: full at-least-once redelivery, with no record that the file was corrupt. Safe direction, silent cause.
- F5 — impl/src/coordination-internals.mjs:318-319 "const start = Number.isSafeInteger(fromSeq) ? Math.max(0, fromSeq - 1) : 0;" while :319 throws "event read limit must be a positive safe integer" for limit. Invalid fromSeq silently returns the whole history; invalid limit throws. Asymmetric validation of the same query.
- F6 — impl/src/process-lifecycle.mjs:36-43 observes "/bin/ps -o pid=,pgid=,lstart=" and uses the locale-rendered lstart string as the cross-restart identity fence ("pidStart"). A locale/TZ change between controller runs makes the same live process report a different pidStart ('mismatch') — identity is environment-dependent, not kernel-observed.
- F7 — impl/src/coordinator.mjs:1145-1147 "this._setTimeout = opts.setTimeout ?? globalThis.setTimeout;" (C4 seam) vs :13033-13035 "_sleep(ms) { return new Promise((resolve) => setTimeout(resolve, Math.max(0, ms))); }". wait()/drain polls bypass the injectable timer seam the file establishes two hundred lines earlier.
- F8 — impl/src/coordination-internals.mjs:117-119 "const confidence = mad === 0 ? Infinity : bestDelta / mad; ... confidence >= 2.0 ? 'HIGH'". "confidence" is dispersion (higher = more anomalous) — inverted from the word's ordinary meaning; every consumer of madConfidenceOf output must know the secret.

## ERRORS

- E1 — HIGH (observed by execution). impl/src/referee.mjs:113-119 tokenize() closes a quoted span with "const lastQuote = command.lastIndexOf(ch);" — the LAST quote in the whole command, not the matching one. Repro of the verbatim function: `npm test -- --grep "one" "two"` (no shell control chars, so looksLikeSimpleCommand true, :97-99) tokenizes to ["npm","test","--","--grep","one\" \"two"] — the second quoted argument is silently destroyed and quotes are glued into the token. The trust gate then re-runs a deployment's verification with a wrong argv and reports the resulting exit mismatch (verification_exit_mismatch) as the worker's failure.
- E2 — HIGH. impl/src/referee.mjs:214 "invalid: 'cwd_outside_sandbox'," is dead data: no consumer exists (see G1), so a configuration refusal is durably recorded as "verification_spawn_unavailable" — the verdict's diagnostic names a cause that did not happen.
- E3 — HIGH on the comment, MEDIUM on the lost-kill path. impl/src/coordinator.mjs:9742-9743 "catch (err) { /* best-effort; the sweep still covers it */ }" and :9757 "cycle.answered = true; // idempotency guard (timer + sweep both reach here)": _sweepDeadlines (:3101-3133) covers worktree authority, approvals/questions, and stop waiters — nothing sweeps stallSeamCycle, and _expireStallCycle is timer-only (sole call site :9742). Worse, answered is set before the preserve/kill chain; if _preserveProgressBeforeReap rejects, :9770-9772 ".catch(noop)" drops it and the consumed cycle is never retried — a stalled worker stays 'working' with the stall flag set and no re-armed kill.
- E4 — HIGH. impl/src/coordination-replay.mjs:1013-1021 "reapExpiredContextPacks(store, repoId) { void repoId; ... if (Date.parse(pack.validity) <= now) reaped += 1; }" counts expired packs and removes nothing; the return field is named "reaped". Its only callers are tests (grep: test/bidirectional-v3-red.test.mjs) — production expiry enforcement must live elsewhere; the wrapper at coordination-store.mjs:12973-12974 keeps a no-op authority alive behind a real-sounding name.
- E5 — HIGH on the asymmetry, MEDIUM on consequence. impl/src/coordination-store.mjs:684 "this._appendFile = opts.appendFile ?? appendFileSync;" — the authoritative ledger append (:1498, :1590) never fsyncs, while every housekeeping artifact does: receipt :929, checkpoint :1009, segment :1337, segment index :1363, ledger rewrite :1452 "fsyncSync(fd);". Replay then refuses a torn tail at startup (coordination-replay.mjs:241-243 "throw new CoordinationIntegrityError('coordination stream has a truncated tail', 'truncated_tail')"), so an OS-level crash can leave the store refusing to start on its own unsynced writes.
- E6 — HIGH. impl/src/referee.mjs:360-376: a coverageCommand run that fails to spawn or exits nonzero produces empty output; the catch at :373-376 then records "coverageNote = ' Coverage report parse failure (non-JSON or malformed stdout) — coverage signal dropped, primary verdict unaffected.'" — an environment/execution failure is durably misreported as a formatting problem, and only surfaces as verification_coverage_unavailable when the primary passed.
- E7 — MEDIUM. impl/src/contribution-service.mjs:113-118 reads the verification lane before enqueuing: "const lane = this.referee?.lane ?? null; if (lane && lane.running >= lane.concurrency) { this.record('contribution.check_queued', { ... position: lane.queued + 1, ... })" — verifyContribution (:120-127) runs afterwards, so the recorded queue position can disagree with the real one. The #269 feature meant to make waiting "read as a queue position and not as a slow verifier" can itself record a wrong position.
- E8 — MEDIUM. impl/src/log.mjs:36-37 advertises "append-aware cross-instance reads", but _load (:99-103) throws "operational log <worker> has a truncated tail" (code operational_log_truncated) when another instance's append lands mid-line between stat and read. A normal concurrent append surfaces as a fatal claim that the file is truncated; the same retry would have succeeded.
- E9 — MEDIUM-LOW. impl/src/coordination-internals.mjs:84-88 eventTime(): "return { eventTimeSeq: seq, eventTime: events[seq - 1]?.ts ?? fallback.ts };" — when the referenced seq is absent the pair is self-inconsistent (a seq coordinate paired with an unrelated fallback timestamp), so derived event-time evidence can silently disagree with its own pointer.

## IMPROVEMENTS

- I1 — referee.mjs tokenize: match quote spans pairwise (scan forward to the next unescaped same-quote) or send any command containing quote characters through the sh -c path; add a test with two quoted arguments.
- I2 — referee.mjs: consume run.invalid in verify()/executionOf and emit a typed code (e.g. cwd-outside-sandbox) instead of verification_spawn_unavailable.
- I3 — coordinator.mjs: route stall-seam expiry through _sweepDeadlines (making :9743's comment true) and, on preserve/kill rejection, clear answered and re-arm instead of ".catch(noop)".
- I4 — coordination-replay.mjs: make reapExpiredContextPacks either invalidate expired packs through the normal append path or delete it and its coordination-store.mjs:12973 wrapper; "reaped" must mean removed.
- I5 — coordination-store.mjs: fsync (or group-commit) the ledger append; if the per-event cost is intentional, document the accepted loss window next to replay's truncated_tail refusal so the durability story is one story.
- I6 — referee.mjs withVerificationLane: expose an atomic admit() that returns the caller's true queue position; record that value in contribution.check_queued instead of a pre-enqueue snapshot.
- I7 — coordination-internals.mjs events(): validate fromSeq with the same TypeError discipline as limit (:319).
- I8 — log.mjs Cursor: on state-file parse failure, move the corrupt file aside (e.g. alongside the cursor path) before resetting the floor, so redelivery bursts are explainable after the fact.
- I9 — contribution-service.mjs check(): document/enforce signal semantics for joined operations (first-signal-wins), or key the in-flight map per caller signal.

## NOVEL INSIGHTS

- N1 — Three encodings of "accepted" coexist and can drift: referee.mjs:480-487 accept(); coordinator.mjs:817-819 defaultAccept() ("verdict.reverified === true && verdict.observedExit === acceptOpts.expectExit"); coordinator.mjs:11171-11176 result() re-derives it inline ("const verdictAccepted = task?.verdict?.reverified === true && task.verdict.passed === true && ..."). A fourth acceptance predicate must be written in three places; result() already diverged (it re-checks reverified/passed rather than delegating).
- N2 — Durability is inverted relative to authority: the ledger (the store's total order) is the only write path without fsync, while checkpoints/segments/receipts — explicitly housekeeping per the comment at coordination-store.mjs:1509-1514 "the checkpoint is HOUSEKEEPING" — are fsynced and atomic-renamed. The housekeeping is crash-safer than the truth it accelerates.
- N3 — "reap" names three different contracts in one codebase: worktree.mjs:1689 reap (real destructive removal with preservation gates), coordination-replay.mjs:1137 reapRunScratchpads (real, batched), coordination-replay.mjs:1013 reapExpiredContextPacks (counting only). The verb no longer carries the contract; E4 is the bug that grows from that drift.
- N4 — Phantom-sweep comments: coordinator.mjs:9743 and :9757 reference a sweep that does not exist (E3) — the comment is the only place the claimed redundancy lives, so a reader audits a safety net that isn't there.
- N5 — Spec drift is recorded in code comments, not specs: worktree.mjs:6-7 "(+ markStopped, which remains a real export per IMPLEMENTATION.md §3 W5 even though D7's literal list omits it)" — two authoritative documents disagree and the tiebreaker lives in a source comment.
- N6 — Field name vs use: coordination-internals.mjs:538 "(row.attemptCount ?? 0) - (row.attemptWindowStart ?? 0) >= store._providerAttemptPolicy.maxAttempts" — "attemptWindowStart" is a count baseline, not a time; every reader must learn this from the arithmetic.
- N7 — Dead data kept alive by a receipt: referee.mjs:214 invalid:'cwd_outside_sandbox' is written into a settled run result nobody reads (E2) — a receipt field whose only function is to be wrong about nothing.
- N8 — The queue-honesty feature (#269) is implemented with the exact race it was meant to eliminate (E7): the harness tells the waiting agent a position that the code does not guarantee, which is the brief's "view says X while the code does Y" in miniature.
