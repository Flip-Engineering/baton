# 11 — The Capability Plane (module overview)

*The fleet's agent-shaped toolset. Each module conforms to `spec/capability-plane.md` (the ACI framework: uniform token-bounded result envelope, capability cards, hub re-runnability, ledger/artifact/task-DAG integration). This doc is the map; the full designs (with real prior art, interfaces, and critic passes) are in `docs/capabilities/`. Every module was researched against real 2025-26 tools and critiqued by an independent design critic.*

## The shape they share

All seven modules are the same idea in different domains: **take a capability that a solo agent gets from harness-native tools, and make it (a) fleet-shared, (b) agent-shaped, (c) orchestration-aware, (d) re-runnable by the hub.** The recurring moves:

- **Shared, not per-worker.** One index / map / recording / knowledge graph the whole fleet reads, amortizing an expensive build across N workers × M turns instead of paying it N×M times. This is stigmergy (doc 10 T3): workers coordinate by reading and writing shared substrate, not by messaging.
- **The unit of value is a structured observation, not a tool transcript.** A debugger returns a `CausalObservation`, not a step-log; search returns symbol-anchored hits, not raw lines; validation returns a proof-carrying attestation, not console output. The ACI envelope (`summary` + bounded `payload` + artifact `refs`) keeps a worker's context small (a search over 500k files costs ~400 tokens, not 40,000).
- **Long ops are supervised.** An index build, a fuzzing campaign, a debug session, a proof search is a task-DAG node — leased, fenced (`turn_epoch`), two-phase-interruptible (supervisor I1/I4/I6), progress-emitting. Capability use is as controllable as a model turn.
- **Claims are re-checkable.** Every output a decision trusts is re-run by the hub (supervisor I7): re-run the test, re-check the proof with a trusted kernel, re-run the search. Forging a result the hub re-verifies in milliseconds is pointless — this is the capability plane serving as the *evidence layer* the control plane's trust model stands on.
- **Outputs promote to knowledge.** Notable results flow to the epistemic plane (doc 08) as provenance-linked records — a reproduction, a build-vs-borrow decision, a proof, a route statistic — so a future fleet doesn't relearn them.

## The seven modules

### 1. `atlas` — Code Discovery & Retrieval → [docs/capabilities/discovery-search.md](capabilities/discovery-search.md)
The `fff`-and-beyond answer. Grounded finding: `fff` (dmtrKovalenko's in-memory agent file-search SDK) is real and ~1000× faster than spawn-per-query ripgrep after one scan — but it's per-process. The 2025-26 consensus is "grep won, but the grep replacement is *three* tools": lexical (ripgrep/Zoekt trigram) + structural (ast-grep CST) + graph (LSP/SCIP, via Serena), with semantic embeddings an opt-in fourth for where grep provably fails. **`atlas` makes that a fleet service:** the base commit is indexed *once* (shared, content-addressed), composed at query time with each worker's cheap **dirty overlay** (a copy-on-write/LSM query model) — the defining multi-agent constraint nobody else solves (N worktrees diverge). Marquee steering primitive: `code_seed` ("look here first") pushes orchestrator attention downward; out-of-scope searches feed the scope-drift signal. Every result carries `index_rev` + `staleness ∈ {fresh|lagging|base_only}` so lag is *seen*, not silently trusted.

### 2. `Vantage` — DAP-driven Debug & Interpretability → [docs/capabilities/debug-interp.md](capabilities/debug-interp.md)
The unit of value is a `CausalObservation`, not a debugger session (InspectCoder measured 33–72 debugger actions per bug — a token firehose). A worker submits an *observation plan* (breakpoints, watches, a record-replay query) and receives a structured causal answer to "why did this fail." **DAP** is the southbound surface (debugpy/Delve/CodeLLDB/rr+gdb are DAP servers), wrapped in a debug-adapter contract mirroring the harness-adapter contract. Live sessions take an **exclusive lease** on the debuggee (CAS, like task claims); **record-replay recordings (rr/TTD) become shared, addressable fleet assets** — one worker's failure is a reproduction any worker (or the hub, for re-verification) can replay deterministically. Observations are provenance-shaped for the epistemic plane.

### 3. The Evidence Ladder — hub-re-checkable validation → [docs/capabilities/math-proof.md](capabilities/math-proof.md)
> **Corrected & re-anchored in review round 2 (doc 13 T1).** The earlier "proof-carrying, crown-jewel" framing was a documentation lie: kernel acceptance means **the proof matches the (worker-influenced) spec**, NOT that the code does what you meant — `sorryAx`/`native_decide`/`axiom` pass a kernel, and a worker who can't find a proof can *weaken the spec until a genuinely valid proof closes* (kernel-green, wrong property — the cheaper attack the green merge-gate selects for). The module is re-anchored on **evidence**, not proof.

**Rigor is a dial:** one primitive ("validate this artifact against this spec at rung R") over a ladder — types → tests → property tests → fuzzing → bounded model checking → SMT/auto-active (Z3/Dafny/Verus/Kani) → machine-checked proof (Lean/Rocq). The load-bearing insight is **forgeability, not pass/fail**: the module converts a worker's "it works" claim into an artifact the hub **independently re-derives with strength the checked party did not author**. The parts that are genuinely fleet-native and vendor-proof (**Bundle A**, the module's real identity): hub re-execution in a fresh sandbox, a hub-computed mutation score (`cargo-mutants`), and the fleet-wide **counterexample corpus** (the fleet's accumulated adversarial memory — impossible in any single-user tool), with an **honest per-language ceiling as the headline** (R0–R3 on most code; R4–R5 on Rust/C; R6 rare). The deep proof rungs and autoformalization (**Bundle B**) are demoted to an **earned-by-demand consumer** of the AlphaProof/DeepSeek-Prover frontier — baton does not reproduce that research race, and **never emits "proven" over a worker-supplied spec.** Autoformalization is not "attacked" by triangulation: N LLMs share training priors, so on an ambiguous spec they converge on the *same* wrong formalization and "agree" fires — a perfect proof of the wrong theorem is worthless, and this is the *dominant* term on exactly the specs worth proving. The trust boundary (doc 13 T5): re-verify against a spec the **human/orchestrator pins**, never a worker restatement.

### 4. `Scratch` — Operational Blackboard & Coordination REPL → [docs/capabilities/coordination-repl.md](capabilities/coordination-repl.md)
The fast lane the user asked for — a fourth memory tempo beside doc 08's three, the *interactive working set*. **Tuple-space verbs** (Linda `write/read/take/notify`), consistency chosen **per cell type** (append-only facts, CAS cells, take-once leases) — deliberately not a monolithic CRDT. The **Bench** is a sandboxed, addressable, **memoized** kernel: "does seed=42 repro?" is computed once and *read* by the whole fleet as a fact, not re-run by each worker. The **Board** is a materialized view over the ledger (dies → replay rebuilds it — the "ledger is the only truth" invariant holds). Ephemeral by design: cells TTL out; a *cited* fact (read N times, referenced by a task) becomes a promotion candidate into the epistemic plane. This is where "I'm about to touch payments/, anyone else?" is a `take` on a lease — stigmergic coordination with the fencing discipline applied.

### 5. Skill Forge & Computer-Use → [docs/capabilities/skills-computeruse.md](capabilities/skills-computeruse.md)
**Reflexive capability growth as a fleet property:** a worker that learns "how to do X" today makes X cheaper for every worker tomorrow. A worker-authored skill is worker-authored *code*, so trust reuses baton's boundary verbatim — OS sandbox not string scan (doc 05 §5), hub-run verification (I7), fleet promotion gated on it. **Computer-use is just another southbound adapter tier** (`cua-adapter`) emitting the same `BatonEvent` stream and obeying the same steer/interrupt/approve verbs — but honestly the flaky, expensive, injection-exposed tier (frontier CUA success rates are far below CLI). ACI not HCI: the orchestrator never sees screenshots; GUI steps are `action.gui_step` events with screenshot *artifact refs*. The capstone links the two: after a computer-use worker succeeds, the forge **distills the flaky trajectory into a deterministic, replayable skill** (AWM/SkillWeaver-style induction) — the vision loop becomes a Playwright script the next worker runs cheaply.

### 6. `Cartographer` & `Quartermaster` — Orientation & Reuse → [docs/capabilities/orientation-reuse.md](capabilities/orientation-reuse.md)
Two faces of one graph. **Cartographer** builds a fleet-shared repo map (tree-sitter+PageRank à la Aider, LSP à la Serena, SCIP à la Sourcegraph) *once* per SHA, not N times; the marquee verb `fleet_orient_worker(w, focus)` is the orchestrator pushing an addressed, scoped subgraph downward ("this touches the auth boundary; here's the map"). **Quartermaster** is a gated broker over free supply-chain oracles (deps.dev, OSV) plus optional commercial Socket enrichment for build-vs-borrow — because AI agents mis-pick/hallucinate dependencies at scale (Endor Labs 2025: only 1 in 5 AI-suggested versions were safe; the Shai-Hulud npm worm shows the blast radius). One graph eventually serves both: reachability can prioritize vuln attention, but incomplete call graphs may never waive a known package-level advisory. Phase 38 promotes freshly reverified external dossier plus actual-SBOM evidence only through explicit Coordinator decision authority; Phase 39 adds exact-expiry validity and forced-refresh coordinate fencing with causal risk `Affects` edges. Phase 40 adds an isolated exact-npm proposed graph and typed actual delta without install or decision authority. Broader map summaries, transitive reachability, additional ecosystems, and internal-choice promotion remain later contracts.

### 7. `Cairn` — Causal Research & Body-of-Knowledge → [docs/capabilities/causal-research-bok.md](capabilities/causal-research-bok.md)
Deepens doc 08's epistemic plane. A **hub-owned, bi-temporal local causal graph** is fed by selective promotion from the ledger and borrows its typed causal/validity discipline from the repository's `project-manager` prior art without creating a runtime dependency. Optional PM-shaped export remains a separate later boundary. The causal backbone is **enforced at write time** (every Decision carries ≥1 evidence edge to a concrete ledger `seq`; monotonic `seq` makes temporal-coherence free — the integrity pattern taken from PM, now an invariant not an audit). Cross-run learning is a **`RouteStat` table of hub-*verified* win/loss per (harness × task-class)** — "Codex weak at auth refactors" is a Wilson-scored counter fed only by I7 outcomes, never worker self-report. Re-poisoning is prevented by construction: recall is pull-only, token-bounded, provenance-framed untrusted, bi-temporally filtered, and itself a ledger event. Honest scoping: most fleets should stop at the near-free run scorecard; build the causal graph only when task-classes recur.

## How they compose (ladders, pipelines, stigmergy)

- **Ladders** (capability-plane §7): validation is the canonical one (cheap `test` rung on every task; escalate to SMT/proof only on the critical path). `atlas` is a search ladder (lexical→structural→graph→semantic). The orchestrator/policy picks the rung by criticality and budget.
- **Pipelines**: `atlas` (find) → `Cartographer` (orient) → `Vantage` (debug) → Validation Ladder (verify) → `Cairn` (remember), passing artifact *handles*, not data — the intermediate never enters an agent's context. ACI's Unix pipes.
- **Stigmergy**: `Scratch` (live), the ledger (operational), git/artifacts (coordinative), `Cairn`/PM (epistemic) are the shared media the fleet coordinates *through* (doc 10 T3) — the modules don't message each other, they read and write shared structure.
- **The trust spine**: every module's re-runnable output feeds supervisor I7. The capability plane is why "worker prose is non-authoritative" (doc 09 §C1) is enforceable rather than aspirational — there is always a cheap re-check.

## Cross-module MVP (what to build first)

Not seven modules — **one thin vertical**: `atlas` lexical+structural search (drop semantic and graph initially) + the Validation Ladder's bottom two rungs (`test`, `proptest`) + `Cartographer`'s `repo_map` + `Cairn`'s run-scorecard (one row per run). That vertical proves the whole plane's thesis: shared agent-shaped tools that keep worker context small, feed hub re-verification, and promote to knowledge — beating N workers each grepping and self-reporting. Every other module (Vantage, the proof rungs, Scratch's Bench, the Skill Forge, computer-use, Quartermaster, Cairn's causal graph) is a later increment conforming to the same `spec/capability-plane.md` contract. The framework is the deliverable; the modules are earned by demand (doc 07 discipline).

## Honest cross-cutting risks (from the critic passes, carried to the red/blue team)

1. **Autoformalization** (module 3) is an unsolved trust leak, not a footnote — the spec→property gap can invalidate the whole proof-carrying story. Priority red-team target.
2. **Shared-index staleness under heavy divergence** (module 1) — the overlay can approach re-index cost; the "when does a worker's overlay trigger a private re-index" threshold is unproven.
3. **Skill-forge trust** (module 5) — worker-authored code shared fleet-wide is a supply-chain surface *inside* baton; the promotion gate is load-bearing and must be adversarially tested.
4. **Computer-use** (module 5) is honestly flaky/expensive/injection-exposed; the design says so — the discipline is knowing when *not* to use it.
5. **BoK amortization** (module 7) — the causal graph is expensive infrastructure that most fleets shouldn't build; the "stop at the scorecard" honesty must survive feature-ambition pressure.
