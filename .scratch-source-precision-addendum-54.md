# 1. Corrected resolution model (replaces addendum A5 and successor S5)

My earlier sentence treated a parse-produced Var index as a resolved binder identity and proposed deriving reference edges from "Var.i" plus the alias table. That was too broad. The source has three distinct parse outcomes and no single indicator of a resolved declaration.

parse_var (kernel 1735-1744) has exactly three branches:
- a successful parse_lookup (1725, innermost-first scan of Parse.sc.stk) yields Var(k, e[1], s), where e[1] is the binder stack entry index at that moment;
- otherwise a dotted spelling yields Ref(q, s) with q from parse_reso;
- otherwise an unbound unqualified spelling yields Var(k, p.sc.frs++, s, Ref(q, s)): a fresh frame slot taken from the per-declaration counter, carrying a Ref fallback. That occurrence is not a bound declaration.

term_higher (kernel 716-728) decides meaning later, not at parse time: a Var with i < 0 returns itself; otherwise list_get(env, i); a null entry falls back to tm.v ?? Ref(tm.k, tm.s), and a function-valued entry is applied to the span. The Var's meaning therefore depends on the instantiation environment.

term_infer (kernel 3337-3352) validates against the checker's actual context: a Var with i < 0 and a value is forced and re-inferred; otherwise pmap_get(ctx, i) supplies the annotation, and a missing entry raises the structured Err "a bound variable". Binder indices are numeric and repeat between declarations and between instantiations, so an index alone carries no identity.

Corrected statement for use in the specification or a design note: "A reference occurrence records the parse outcome (bound to a binder entry, dotted qualified name, or unbound spelling with a fresh-slot fallback), the binder scope and provenance from the declaration and checker context it belongs to, the instantiation environment consulted by term_higher, and the phase reached (parsed, converted, checked). A parse-qualified name is not a completed checked reference; occurrence identity requires the owning declaration and context, not the numeric index. Unsupported, failed or absent targets are reported unresolved with their actual evidence by using the frontend's own resolution, conversion and checking, with no parallel parser or resolver and no new public API."

# 2. Dispositions recorded

S1 accepted with the rendering-only scope: a type fact may stay a structured term; only a rendering requires term_lower (kernel 822) on the HTerm (Def.T/ADT.T 311-312, Infer.ty 348) before term_show (1295, LTerm), and that rendering retains its binder-name list. Declared/inferred status and display representation remain separate dimensions. My A4 wording is corrected accordingly: rendering is an operation on a type fact, not a requirement that every type fact be printed.

S2 rejected, and I withdraw the proposal. d27 owner_admission (1849-1854) admits a recorded active owner and, for a stopped owner, only owned query-control recover/release and owned runtime release; every ordinary computation subject refuses. module-resolution is an ordinary query and already falls under that rule: new inspect/install requires an active owner; an existing installation outcome stays readable through context-result; a retained managed installation duty uses the existing owned recovery/release path. Any stopped-owner inspect permission would be a separately justified Core/Lifecycle policy change, not a wording fix. This raises no blocker in the present specification.

S3 accepted with admission and minima explicit: a selected trusted package process is an admitted provider invocation; its process creation is recorded; target effects keep the common mandatory effect minimum union the module's declared additions; a declaration alone grants no launch before query admission or execution-placement authority; discovery stays metadata-only. I withdraw any reading of compiler checking as unconditionally effect-free, and no broad target authority follows from provider identity.

S4 accepted with instrumentation, and my "capture around split calls" framing is corrected: the exported wrappers cannot expose internal parse state. parse_book (2594-2595) creates a local Parse p holding sc and al; 2600 resets p.sc per declaration; parse_def and parse_close mutate p internally. Binder, alias, statement, fill and checker-success events therefore require an explicit reviewed hook or instrumented bridge inside the same pinned frontend, with derived source identity and semantic-equivalence/mutation qualification. Whole-call start/end supports only whole-phase outcomes. No hook exists because the specification requests one, and I claim none as an existing export.

S6 accepted: the TypeScript `--engines` observation stands (provider.mjs resolves before the engines branch; lib/resolve.mjs requires the library and digests lib/typescript.js). Reclassifying that mode as selected-module readiness is a valid candidate handoff; baseline discovery consumes the trusted declaration data; no additional public provider metadata protocol and no provider change are requested before the shared handoff is settled.
