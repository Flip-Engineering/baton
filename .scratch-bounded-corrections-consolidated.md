# B1. Resolution model (replaces addendum A5 and successor S5; unchanged from addendum-54, restated as the settled form)

parse_var (kernel 1735-1744) has three outcomes: bound -> Var(k, e[1], s) from parse_lookup (1725); dotted -> Ref(q, s) from parse_reso (1751); otherwise an unbound unqualified spelling -> Var(k, p.sc.frs++, s, Ref(q, s)), a fresh frame slot with a Ref fallback and not a bound declaration. term_higher (716-728) decides meaning later through env (i < 0 returns itself; null list_get falls back to tm.v ?? Ref(tm.k, tm.s); function entries are applied). term_infer (3337-3352) validates against the checker's actual ctx by numeric index and raises Err "a bound variable" when absent. Binder indices repeat between declarations.
Settled requirement: an occurrence records its parse outcome, owning declaration and binder scope, the instantiation environment consulted, and the phase reached; a parse-qualified name is not a completed checked reference; unresolved targets are labelled with their actual evidence using the frontend's own resolution/conversion/checking; no parallel parser or resolver and no new public API.

# B2. Rendering (C1, accepted with the rendering-only scope)

A type fact may remain a structured term. When it is rendered, Def.T/ADT.T (311-312) and Infer.ty (348) are HTerm, so term_lower (822) precedes term_show (1295), and the rendering retains its binder-name list. Declared/inferred status and display representation are separate dimensions; no requirement that every type fact be a printed string.

# B3. Admission and effect sequencing (C2/C3, accepted as refined)

A selected trusted package process is an admitted provider invocation: query admission and the core's mandatory effect minimum precede a trusted provider launch, and the process creation is recorded. A declaration alone grants no launch before admission or execution-placement authority. Compiler checking is admitted computation, not an unconditionally effect-free read, and provider identity grants no broad target authority. Per Code54, the mandatory minimum is a common operation minimum computed, enforced and unioned by core; my earlier C5 proposal that each module declare its own mandatory minimum is withdrawn, and numeric domain precision is already governed by the typed schema and the exact result-domain clauses rather than by any transfer of authority to unvalidated raw tokens.

# B4. Event instrumentation (C4, accepted as corrected)

Parse/check events cannot be obtained by wrapping the exported calls: parse_book (2594-2595) keeps a local Parse p holding sc and al, 2600 resets p.sc per declaration, and parse_def/parse_close mutate p internally. Binder, alias, statement, fill and checker-success events therefore require an explicit reviewed hook or instrumented bridge inside the same pinned frontend, with derived source identity and semantic-equivalence/mutation qualification; whole-call start/end supports whole-phase outcomes only. No hook exists because the specification requests one, and none is claimed as an existing export.
